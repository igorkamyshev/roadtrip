# web

The client: the one screen of the site (spec «Экран», «Состояние, ссылка и память браузера»), variant C of the prototype (branch `claude/you-mshpw6`, `prototypes/screen/`, `#c`), whose layout and copy it ports. Vite, React, TanStack Router, Query and Virtual, MapLibre GL. `vite build` writes `dist/`, which the Worker `roadtrip` serves as its static assets (`worker/wrangler.jsonc`, `"assets"`) before its own routes.

## Where things are

- `src/main.tsx`: PostHog on the production host (`src/analytics/`, «Analytics» below), the opening state (`src/state/startup.ts`: the link, else the saved state, else the defaults), then the router (its context says where the opening state came from) and the Query client.
- `src/router.tsx`: one route `/` with hash history; `validateSearch`, `parseSearch` and `stringifySearch` from `src/state/search.ts` keep the link literal: `/#/?p=44.81760,20.45730&h=3&cit=RUS,SRB&visas=GEO,SCHENGEN`.
- `src/state/`: the state in the link and its defaults (`search.ts`: the origin, N, the citizenships, Sherpa's passports sorted, `RUS` by default, and the held visas, `rules`' `HELD_VISAS` sorted, none by default and left out of the link then; anything else in `cit` or `visas` takes the default), the origin as a point to 5 decimals (`point.ts`), the saved snapshot (`startup.ts`), the changes, each a `navigate` with `replace: true` plus the snapshot, and how the origin was set, which the link does not keep (`use-screen-state.ts`: `start`, `setStart`), and what besides the origin and N a ring is asked for (`settings.ts`: the citizenships and the held visas).
- `src/ring/`: `fetch-ring.ts` is the one place a ring request starts and ends; `use-ring.ts` holds the rings in TanStack Query (infinite `staleTime` and `gcTime`, no retries, the previous ring of the same origin as `placeholderData`) and the hours in memory for the slider's dots. A `visa_rules_missing` is no ring: once the screen asks for something else it is removed from memory, so its hours get no dot and asking for it again asks the Worker (its card says «Попробуйте позже»).
- `src/start/`: the origin. `geolocation.ts` (the browser's position and why it failed), `start.ts` (`Start`: the origin and how it was set, `StartMethod` `geolocation`, `search`, `pin`, `link` or `saved`, with the city of the search; `startLabel`, the phrase's label: the city of the search, «на карте» for the pin, else the nearest city, «на карте» until the cities file comes or if it cannot), `start-sheet.tsx` («Откуда едем»: the search, «Указать на карте», «Где я» and the note when the browser gave no position).
- `src/map/`: `map-view.tsx` (the MapLibre map, the camera, the pin, a tap on a city), `overlay.ts` (the sources and layers over the basemap, in the order the screen draws them: the hatching of closed countries, the ring, the ring's cities, the origin), `basemap.ts` (the basemap's style).
- `src/cities/`: the cities in the ring (#32). `cities.ts` fetches the cities file (`/data/cities.json`, data's `build-cities`, format `data/cities-file`) once into TanStack Query (`useCities`); `in-ring.ts` picks the ring's cities (`citiesInRing(cities, ring, access)`: inside the MultiPolygon, by a band index of its edges, in a zone `access` opens, biggest first); `city-card.tsx` (the card of a city and «и ещё K / Все города →»), `cities-sheet.tsx` (the list of all, TanStack Virtual, rows of a fixed height), `copy.ts` (population, the entry mode's mark, Russian plates in the EU by `rules/eu`, the route in Google Maps), `carousel.ts` (the card in the carousel's middle when it stops, scrolling a card into it), `search.ts` (`searchCities(cities, text)`: up to 8 by the start of the Russian or local name, never by a later word, case and ё aside, a hyphen as a space, bigger cities higher; `searchable`, which the sheets' filters use too), `nearest.ts` (`nearestCity(cities, { lat, lon })`: by great-circle distance, no limit; its `zone` is its country).
- `public/basemap/`: Protomaps' fonts and sprites, served as they are (below, «Basemap»).
- `src/screen/`: `screen.tsx` puts the screen together and keeps the chosen city (the carousel's middle card, a city tapped on the map or picked in the list; a new ring chooses none); `phrase.tsx` (with `VisaRulesDate`, «визовые правила от <дата>»), `slider.tsx`, `first-card.tsx` (the spec's table of states), `sheets.tsx` («Гражданство», «Мои визы», «Что важно знать», and `Sheet`, which every sheet is), `held-visas.ts` (what each of Schengen, the USA, the UK and Canada opens: the rows of `rules/held-visas`' table acting today in UTC for the citizenships chosen, the same table and `actingExemptions` the Worker uses), `countries.ts` (Russian names: `Intl.DisplayNames('ru')` by the alpha-2 of `rules/countries`, our own for `RKS` and `NX`; «РФ» in the phrase; `visaName`, «Шенген» and «США», for the phrase and the city card's «по визе: <страна>»), `copy.ts` (hours and plurals), `icons.tsx`.
- `src/styles.css`: the prototype's CSS for variant C, its tokens on `:root` with the dark scheme.

## For the next tickets

- **Map layers.** `src/map/overlay.ts` says where each goes. Add sources and layers in `addOverlay`, and a `show…` function the map view calls with props.
- **The hatching.** The layer `closed-hatch` fills the zone outlines (source `zones`, fetched from `/data/zones.json`, data's `zoneOutlines`) whose code `access` of the answer shown says `closed`, by a filter (`showClosed`); without an answer with `access`, nothing. The outlines are the dataset's: `pnpm --filter data build-graph <extract> <out.graph> --outlines web/public/data/zones.json` puts them where `vite dev` and `vite build` take them (gitignored); the deploy puts the dataset's there before the build (`worker/README.md`, «Deploy»). Without the file the map has no hatching and nothing else changes.
- **The cities file** goes there too: `pnpm --filter data build-cities <graph> web/public/data/cities.json --countries RS,HU,…` for a region (`data/AGENTS.md`), the dataset's in the deploy. Without it the ring's card says «В кольце …» with no count and the carousel has no cities.
- **The phrase.** `Phrase` takes `settings` (after «в пути.»: «Гражданство [РФ], мои визы: [нет]», each a `PhraseToken` that opens its sheet), `footer` (`VisaRulesDate`) and `startLabel` (`startLabel()` of `src/start/start.ts`). Sheets are `Sheet`s (`src/screen/sheets.tsx`).
- **The cities (#33, #34).** `useCities()` has the cities file (`City`: id, Russian name or else local, the local name when it differs, place, population, zone), and `screen.tsx` the ring's (`shownCities`, undefined while the ring is an old one or the file has not come): the search (`searchCities`) and the nearest city (`nearestCity`) take the same list, #34 counts `cities_count` and `countries_count` from it as the first card does. The carousel's other points of interest would go where `CityCard` does. A city card's mark of a held visa comes from `access` of the answer (`visa`: `SCHENGEN` or an alpha-3): «по визе Шенгена», else «по визе: » and `visaName`; an `evisa` that a row of the exemptions' table gives is «оформить заранее», as any e-visa.
- **Analytics.** A new event goes in `src/analytics/events.ts` (its properties) and is sent with `send` of `src/analytics/posthog.ts`, or through `ScreenAnalytics` when it needs the place (below, «Analytics»).

## Analytics

`src/analytics/` (spec «Аналитика и ошибки», «Браузер»; decisions #16–#18):

- `posthog.ts` starts `posthog-js` in `main.tsx` before anything else, and only on the production host `roadtrip.kamyshev.me`: anywhere else (`vite dev`, `vite preview`, a copy) nothing is initialised and `send` does nothing. The settings are the spec's: `defaults: '2026-08-30'` (a page view only when the path changes, never for the link's `#…`, and `#…` cut from every URL in the events), `capture_exceptions`, no session recording, the proxy `https://r-rt.kamyshev.me` as `api_host`, `ui_host`, and `tracing_headers` for the production host, so the ring requests carry `X-POSTHOG-DISTINCT-ID` and `X-POSTHOG-SESSION-ID` for the Worker's events and errors. The SDK's tracing headers and exception autocapture are bundled rather than loaded from the proxy after `init`, so the first ring request of a load carries the ids and an error while the page loads is caught.
- `events.ts`: the screen's own events and their properties, as decision #18 has them: `start set`, `geolocation failed`, `ring result`, `link opened`. Never the origin: a place is the nearest city of the cities file (`start_city`, `start_city_id`) and its country (`start_country`).
- `screen-analytics.ts` says when each goes; `use-screen-analytics.ts` feeds it from the screen (`screen.tsx`). `link opened` goes from `main.tsx`, `geolocation failed` from the screen's failed `locate()`.
  - `start set` and `ring result` wait for the cities file for their place (and a ring for its `cities_count` and `countries_count`, counted as the first card does), and go with the time they happened; without the file they go without them.
  - `ring result` is one for each ring asked for: the load, the slider let go (it changes N only then, so moving it sends nothing), other settings, another origin, «Повторить». A ring in memory is `memory` with `wait_ms` 0; a request ends with its answer (`source` the Worker's), its failure (`too_many_requests`, `error`), or `abandoned` when the screen asks for something else first, at once, or when the page goes away (`pagehide`), by `sendBeacon`, as everything still waiting.
- The map's container has `ph-no-deadclick` and `ph-no-rageclick`: a tap on the map changes only the canvas, and PostHog's dead clicks (once the project turns them on) took every tap for one.

### Source maps

`@posthog/rollup-plugin` in `vite.config.ts` uploads the build's source maps to PostHog, so that the stack of an error in the browser reads as the source. It runs only when the build has two variables, which Workers Builds gives the build of the Worker `roadtrip` (its trigger's build variables, not the Worker's vars):

- `POSTHOG_PERSONAL_API_KEY`: a secret, the Owner's personal key (`phx_…`) with the scope «error tracking: write». Never in the repository.
- `POSTHOG_PROJECT_ID`: `718601`, not secret.

With both, the plugin writes a chunk id into each JS file, uploads the maps under the release `roadtrip-web` of the commit's git SHA (`WORKERS_CI_COMMIT_SHA`, else `git rev-parse HEAD`) and removes the `.map` files from `dist/`: the deploy must ship exactly that `dist/`. A key PostHog refuses fails the build. Without them, as locally, in CI and in the screen tests, the plugin is left out: the build is as before and uploads nothing. The plugin runs `posthog-cli`, which downloads its binary from `releases.posthog.com` on first use (pnpm runs no install script of `@posthog/cli`).

## Basemap

`src/map/basemap.ts` (spec «Экран» → «Карта»): the style of `@protomaps/basemaps` over the vector tiles of `GET /tiles/{z}/{x}/{y}`, which the Worker serves from the world's PMTiles archive (`worker/README.md`), credited «Protomaps © OpenStreetMap».

- The flavor is `light`, or `dark` when the page is in the dark scheme, read once when the map is made.
- Labels: Protomaps' `lang: 'ru'` writes the Russian name, else the English one, with the local name on a second line. Every label that shows a name gets `coalesce(name:ru, name)` instead: Russian, else local, on one line, countries too. The regions keep their abbreviation below z6; house numbers and road shields keep their text.
- Fonts and sprites are ours, in `public/basemap/`, from `protomaps/basemaps-assets` at `028c18f`: the v4 sprites of `light` and `dark`, and of the three fontstacks the style uses (`Noto Sans Regular`, `Medium`, `Italic`) only the glyph ranges of Latin, Greek, Cyrillic, Armenian, Georgian and punctuation: `0-255`, `256-511`, `512-767`, `768-1023`, `1024-1279`, `1280-1535`, `4096-4351`, `8192-8447` (2.2 MB; every range is 13.5 MB). MapLibre draws a character of any other range with the browser's own font, and the scripts that need shaping (Devanagari, Thai and the like) and Chinese, Japanese and Korean always. `fonts/OFL.txt` is the fonts' licence; the sprites derive from the MIT-licensed `tangrams/icons`.
- Another range or flavor: copy it from `https://raw.githubusercontent.com/protomaps/basemaps-assets/028c18f/fonts/<fontstack>/<range>.pbf` (or `sprites/v4/<flavor>{,@2x}.{json,png}`) into the same path under `public/basemap/`.

## Tests

The screen's seam (spec «Решения по тестам», 3) is Playwright on the built client: `e2e/*.spec.ts`. `/api/ring` is a scripted double that records each request (its headers too) and answers or holds it, the tiles of `/tiles/` are empty vector tiles, `/data/zones.json` gets a few squares around Belgrade (`ZONE_OUTLINES`), `/data/cities.json` real cities around Belgrade (`CITIES`, or a test's own through `serveCities`), and every other host is cut off in every test (`e2e/fixtures.ts`, the `network` fixture, which records both); geolocation comes from the context's permissions, time from `page.clock`. The tests read the screen by role and text and the map by its sources, layers and the hatching's filter, through `window.__roadtripMap` (`e2e/screen.ts`), never by pixels; a tap on a city goes where the map projects it (`tapMap`). `visaRules()` in the fixtures adds `access` and `visaRulesLoadedAt` to an answer.

PostHog's tests (`e2e/analytics.spec.ts`) open the same build at `https://roadtrip.kamyshev.me` (`openInProduction`): the fixtures answer that host from the preview server, so the client runs PostHog there as in production, and nothing in it knows of tests. The `posthog` fixture is PostHog behind its proxy (`PostHogDouble`): it records the events the page sends, the beacons marked, answers the remote config with the project's own (`captureDeadClicks` aside) and serves the SDK's lazy scripts from the installed `posthog-js`; the page shows the SDK a person's phone, not an automated browser, whose events it drops. Leaving the page is its `pagehide` (`leave`): Playwright does not see the beacons of a page that is really gone.

```bash
pnpm e2e                                  # at the root: builds the client, serves it with `vite preview` on :4173, runs Chromium
pnpm --filter web exec playwright test e2e/ring.spec.ts   # one file
E2E_PORT=4180 pnpm e2e                    # on another port, while a second checkout runs its tests
pnpm --filter web dev                     # the dev server; it sends /api to the worker's `pnpm dev` on :8787 (worker/README.md)
```

`@playwright/test` is pinned to the Chromium of the environment (`PLAYWRIGHT_BROWSERS_PATH`); CI installs that browser itself (`.github/workflows/checks.yml`).
