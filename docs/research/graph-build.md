# Где собирать граф дорог

Ответ на тикет [#14](https://github.com/igorkamyshev/roadtrip/issues/14) карты [#1](https://github.com/igorkamyshev/roadtrip/issues/1). Дата исследования: 2026-11-07.

Вопрос тикета: где раз в месяц собирать граф дорог мира из OSM — в GitHub Actions этого публичного репозитория или в Cloudflare (Workflows, Containers, R2). В граф входят `highway=motorway…tertiary` со съездами `_link`, без паромов, и узлы `barrier=border_control`. Готовый граф весит ~0,6–0,7 ГБ (тикет [#4](https://github.com/igorkamyshev/roadtrip/issues/4)). Сборщик свой, на TypeScript, тяжёлую фильтрацию делает osmium ([ADR 0001](https://github.com/igorkamyshev/roadtrip/blob/main/docs/adr/0001-own-ring-engine.md), тикет [#8](https://github.com/igorkamyshev/roadtrip/issues/8)). Правила границ применяются при расчёте, поэтому граф пересобираем только ради изменений дорог.

Пометки у чисел:

- **[док]** — из документации или прайса, ссылка рядом;
- **[замер]** — мой пробный запуск, методика в разделе [«Как мерил»](#как-мерил);
- **[оценка]** — мой расчёт, исходные числа указаны.

## Вердикт

1. **Собираем в GitHub Actions этого репозитория.** Пробный прогон отфильтровал и склеил дороги всего мира из 9 частей Geofabrik за 3 ч 16 мин из 6 ч допустимых [замер]. Для публичного репозитория это бесплатно [док][gh-billing]. Рабочие файлы заняли на пике 35 ГБ диска из 120 ГБ свободных, память — 8,4 ГБ из 16 [замер].
2. **Узкое место — скачивание с Geofabrik.** Скорость прыгала от 2,8 до 126 МБ/с: Азия (16,5 ГБ) качалась 100 мин, Северная Америка (19,5 ГБ) — 2,6 мин [замер]. Фильтр всех частей занял 27 мин [замер]. Поэтому в боевом workflow каждую часть качаем и фильтруем в своей matrix-джобе параллельно, а склеиваем в отдельной джобе. Тогда время прогона — это самая медленная часть, ~0,5–2 ч [оценка]. У каждой джобы свои 6 ч, а бесплатный план запускает до 20 джоб одновременно [док][gh-limits].
3. **Части берём на одну дату и без России.** Geofabrik обновился посреди прогона, и 171 дорога пришла в двух версиях [замер]. Файлы с датой в имени (`russia-261106.osm.pbf`) есть на сайте [док][gf-russia], их и надо качать. Часть «Россия» лишняя: остальные части покрывают её целиком, только в ней лежит 21 дорога из 599 809 [замер]. Дыр между частями нет, а на семи проверенных переходах дороги через границы частей после склейки на месте [замер].
4. **Раз в месяц.** `schedule` плюс `workflow_dispatch`. Расписание в публичном репозитории отключается после 60 дней без активности [док][gh-schedule]. Ежемесячный PR агента с таблицей исключений (тикет [#11](https://github.com/igorkamyshev/roadtrip/issues/11)) держит репозиторий живым, но нужен сигнал, если граф не обновился.
5. **Готовый граф кладём в образ контейнера**, тем же workflow через `wrangler deploy`. Копию каждой версии — в R2 как архив. Чтение графа из R2 на каждом холодном старте заняло бы ~15 с [оценка по замеру 45 МБ/с], а образ стартует за 1–3 с по документации [док][cf-faq]. Холодный старт образа с графом всё равно проверяем первой задачей реализации (#8).
6. **Цена — $0.** Архив в R2 на ~10 версий занимает ~7 ГБ. Это бесплатно в пределах 10 ГБ или ~$0,1 в месяц по $0,015 за ГБ, если бесплатный объём уже занят подложкой карты из тикета [#7](https://github.com/igorkamyshev/roadtrip/issues/7) [док][cf-r2-pricing]. В секреты репозитория кладём API-токен Cloudflare для деплоя и ключи R2 для архива.
7. **Cloudflare целиком тоже справится, но сложнее.** Германия (4,9 ГБ) скачалась, отфильтровалась и легла в R2 за 2 мин 49 с в Container standard-4 [замер]. Мир — это ~60–70 частей и отдельный контейнер для склейки, ≈$0,3 за прогон по прайсу [оценка]. Кода оркестрации в разы больше, а нужная политика контейнеров в бете [док][cf-sched]. Временный сервер (€0,34 за 3 ч [док][hetzner]) держим как запасной вариант.
8. **Планета одним файлом — возможное ускорение.** Первый 1 ГБ планеты с зеркал шёл со скоростью 48–116 МБ/с, вся планета весит 95,7 ГБ [замер]. Это ~1 ч на весь путь [оценка], но нужно ~100 ГБ диска, а GitHub гарантирует только 14 ГБ [док][gh-runners]. Целиком не проверял.

## 1. Пробный прогон в GitHub Actions

Раннер мирового прогона: Azure westus, AMD EPYC 7763, 4 vCPU, 15 GiB RAM и 3 GiB swap, один диск на 150 ГБ [замер]. До чистки свободно 86 ГБ, после удаления предустановленного софта — 120 ГБ, чистка заняла 2 мин 36 с [замер]. Смоук-прогон попал на другой раннер (centralus, EPYC 9V74) с тем же диском и теми же 120 ГБ после чистки [замер]. По документации раннер публичного репозитория — это 4 CPU, 16 ГБ RAM и 14 ГБ SSD [док][gh-runners]. Значит, 120 ГБ — факт на сегодня, а не гарантия.

## 2. Пробный прогон в Cloudflare

На аккаунте владельца поднял Worker `roadtrip-probe-builder` с Durable Object, Container и Workflow, плюс бакет R2. Всё через API, без wrangler и без Docker: свой образ не собирал. Контейнер запускал на управляемом образе `cloudflare/debian-trixie`, это Node.js 24 на Debian trixie slim [док][cf-images]. Такой образ доступен только с политикой планирования `durable_object`. Она в публичной бете с 2026-09-30, и в ней размер инстанса выбирает сам Durable Object при `ctx.container.start()` [док][cf-sched].

Шаги одного прогона в Workflow:

1. DO запускает контейнер с `entrypoint: ["sleep", "infinity"]`. Через `exec()` [док][cf-do-api] ставит `osmium-tool` из apt, качает выгрузку Geofabrik и запускает `osmium tags-filter` в фоне.
2. Workflow раз в 10 с читает лог через `exec()`.
3. DO читает результат командой `cat` и пишет её stdout в R2 через `FixedLengthStream`.
4. DO читает объект из R2 обратно в контейнер через stdin `exec()` и сверяет байты.
5. DO гасит контейнер через `destroy()`.

Результаты, все [замер]:

| Шаг | Люксембург, standard-1 (½ vCPU, 4 GiB, 8 GB) | Германия, standard-4 (4 vCPU, 12 GiB, 20 GB) |
| --- | --- | --- |
| Старт контейнера и запуск задачи | 0,12 с | 0,12 с |
| apt-get osmium-tool 1.18.0 | 7 с | 10 с |
| Скачивание с Geofabrik | 48 МБ за 3,3 с, 14,6 МБ/с | 4,88 ГБ за 53 с, 92 МБ/с |
| `osmium tags-filter` | 11 с, CPU 53 %, пик RSS 2,0 ГБ | 80 с, CPU 360 %, пик RSS 2,1 ГБ |
| Результат | 2,2 МБ, 17 778 ways | 174 МБ, 1 462 255 ways |
| Запись в R2 | 0,45 с | 10,7 с, 16 МБ/с |
| Чтение из R2 в контейнер | 0,3 с | 3,9 с, 45 МБ/с |
| Весь Workflow | 32 с | 2 мин 49 с |

Что выяснилось по дороге [замер]:

- Без wrangler контейнер к DO не привязывается, пока в метаданных загрузки Worker нет `containers: [{ class_name }]`. Иначе API отвечает «Durable Object namespace is not Container-enabled».
- Первый прогон потерял контейнер через ~40 с: следующий `exec()` упал с «cannot be called on a container that is not running». По документации без `setInactivityTimeout()` контейнер останавливается вскоре после того, как DO стал неактивен [док][cf-do-api]. Таймаут стоял и в первом прогоне, но его ошибку я не логировал. Когда добавил `monitor()` в `waitUntil` и опрос раз в 10 с, контейнеры доживали до конца. Точную причину не установил.
- standard-4 стартует с MemTotal 4 GiB, память добавляется по запросу. Node выделил 11 GiB, после этого MemTotal стал 12,0 GiB, примерно 2 с на каждый GiB.
- Контейнеры поднимались в iad14 и iad15 (Ашберн).

Не пробовал: Европу по странам и склейку мира в Cloudflare. Ниже оценка.

### Мир целиком в Cloudflare [оценка]

- Диск контейнера — до 20 GB [док][cf-limits]. Европа (35,4 ГБ) и Северная Америка (19,5 ГБ плюс результат) целиком не помещаются, их берём по странам. Это ~50 стран Европы и 3–4 части Северной Америки, остальные 7 частей влезают целиком. Всего ~60–70 частей.
- Одна часть по замеру на Германии стоит ~11 с скачивания и ~16 с фильтра на каждый ГБ при 4 vCPU. На все ~86 ГБ без России это ~40 мин работы standard-4. Четыре контейнера параллельно справятся за ~10 мин, плюс склейка.
- Склейка: отдельный standard-4 забирает отфильтрованные части из R2, делает `osmium merge` и `add-locations-to-ways`, запускает сборщик на TypeScript. На GitHub `osmium merge` занял 158 с при 1,0 ГБ RSS, а `add-locations-to-ways` — 159 с при 8,4 ГБ RSS [замер], так что 12 GiB хватает. Отфильтрованные части весят ~4 ГБ, из R2 в контейнер это ~1,5 мин при 45 МБ/с.
- Цена прогона по прайсу [док][cf-pricing]: память ~12 GiB·ч ($0,10), CPU ~130 vCPU·мин ($0,15), диск ~20 GB·ч ($0,005). Итого ~$0,25–0,3. Workers Paid включает 25 GiB·ч, 375 vCPU·мин и 200 GB·ч в месяц, так что прогон, скорее всего, ничего не добавит к счёту. Но включённый объём делят все контейнеры аккаунта.
- Сложность. Сам Workflow это выдержит: до 10 000 шагов, время шага не ограничено [док][cf-wf-limits]. Но в коде — ~70 параллельных веток с ретраями, список стран в синхроне с Geofabrik, ограничение параллельных скачиваний с Geofabrik, склейка в отдельном контейнере, бета-политика, shell внутри контейнера и TypeScript снаружи. В GitHub Actions то же самое — один YAML на несколько десятков строк.

## 3. Временный сервер [док]

- Hetzner CPX42: 8 vCPU, 16 ГБ RAM, 320 ГБ NVMe, €0,1122 в час без НДС. Оплата почасовая, с потолком в месяц [док][hetzner]. 3 часа — ~€0,34.
- DigitalOcean Basic 16 GiB: 8 vCPU, 320 GiB SSD, $0,143 в час. Оплата посекундная, минимум 60 с [док][do]. 3 часа — ~$0,43.
- Нужны токен облака в секретах GitHub и скрипт, который создаёт сервер, ждёт сборку и удаляет сервер даже при ошибке. Забытый сервер стоит денег.
- Это запасной вариант. Он нужен, только если раннер GitHub перестанет давать диск сверх гарантированных 14 ГБ или сборка перестанет влезать в 6 ч.

## 4. Куда класть готовый граф

- **Образ контейнера.** Cloudflare обещает холодный старт 1–3 с, «dependent on image size» [док][cf-faq]. Образ на ~1 ГБ влезает в диск standard-1 (8 GB) [док][cf-limits], на аккаунт хранится до 50 GB образов [док][cf-limits]. Холодный старт такого образа ещё не мерили, это первая задача реализации по #8.
- **R2 с чтением при старте.** Чтение из R2 в контейнер через DO и stdin `exec()` шло со скоростью 45 МБ/с [замер]. Граф на 0,6–0,7 ГБ грузился бы так ~15 с на каждом холодном старте [оценка]. Прямое чтение из контейнера по HTTP я не мерил.
- **Заливка из GitHub Actions.** `wrangler r2 object put` принимает файлы только до 315 МБ, для больших нужен S3-совместимый клиент [док][cf-r2-upload]. Для образа нужен `wrangler deploy` с Docker; Docker на раннере есть.

Вывод: граф едет в образ контейнера при ежемесячном деплое, а в R2 лежит архив версий для отката и отладки. Если холодный старт образа на ~1 ГБ окажется медленным, переходим на чтение из R2 и меряем прямое чтение по HTTP.

## Как мерил

- **GitHub Actions.** Временный workflow `.github/workflows/graph-build-probe.yml` в ветке `research/graph-build` ([файл на коммите 6158047][probe-yml]). После исследования удалён. Смоук-прогон на Антарктиде и Центральной Америке — [run 42372140898][probe-smoke], прогон мира — [run 42372554371][probe-run]. По шагам:
  1. Удаляю предустановленный софт (Android SDK, .NET, GHC, CodeQL, JVM и др.) и образы Docker, печатаю `df -h`.
  2. Ставлю `osmium-tool` 1.16.0 из apt Ubuntu 24.04.
  3. Считаю по полигонам из `index-v1.json` Geofabrik и суше Natural Earth 1:10m [ne], какая суша не входит ни в одну часть и какую сушу покрывает только одна часть. Площадь приблизительная: градусы × cos широты.
  4. Качаю первый 1 ГБ планеты с нескольких зеркал (HTTP Range).
  5. По очереди для каждой части: `curl` на диск раннера, `osmium tags-filter <part> w/highway=motorway,…,tertiary_link n/barrier=border_control` под `/usr/bin/time -v`, счёт ways и nodes, удаление исходника.
  6. Ищу ways, которые лежат в нескольких частях, и сверяю их версии.
  7. `osmium merge` всех частей, `osmium fileinfo -e`. Если у объекта несколько версий — `osmium time-filter`. Потом `osmium check-refs` и `osmium add-locations-to-ways`.
  8. Смотрю дороги в рамках вокруг известных переходов между частями: Верхний Ларс, Сарп, Нарва — Ивангород, Троицк, Кяхта, Таба, Сеута, Вутунг, Текун-Уман.

  Ошибка в шаге 8: рамки я вырезал `osmium extract` из файла после `add-locations-to-ways`, а этот шаг по умолчанию выбрасывает узлы без тегов. Поэтому в рамку попали только ways с хотя бы одним тегированным узлом внутри. Найденные ways и их части верны, а «0 ways» у Сарпа ничего не значит.
- **Cloudflare.** Worker, DO, Workflow, Container и бакет R2 с префиксом `roadtrip-probe-`, созданы и удалены через API Cloudflare 2026-11-07. Код Worker — ~180 строк на JS, в репозиторий не клал. Прогоны: Люксембург на standard-1 дважды (первый потерял контейнер), Германия на standard-4, тест памяти на standard-4. Всё удалено, удаление проверено листингом: Worker, пространство DO, Workflow с инстансами, приложение Containers, два объекта R2 и бакет. Свой образ не публиковался.
- **Временный сервер.** Не запускал, только прайсы.
